# 原生 CC 写入后端执行计划（PRD v1.3）

## 决策与完成定义

- 逐项目显式启用信任项目模式；只读任务仍使用原有快照和 bubblewrap。
- 写入任务由 Codex1CC 后台执行器运行 `claude -p --output-format stream-json`，在独立 Git worktree 中使用编辑与命令工具。`claude --bg` 不能与 `-p` 合用，因此首版不接管已由 Claude 自己启动的后台会话。
- CC 可在任务分支创建本地提交。完成、提问和失败经现有持久事件投递给 Codex；不调用模型轮询。Codex 核对真实 diff、提交和测试证据后再决定完成或续接。
- 信任模式中的 Bash 可以访问本机其他路径和网络；路径声明只作准入及事后审查，不是沙箱。不要把“不可推送或部署”的提示词当作硬权限。

## W1：配置与准入

项目配置增加 `write_backend: {"enabled": true, "write_paths": ["src", "tests"]}`。`"."` 明确授权整个仓库，默认关闭。任务通过 `actions=["read","write","execute"]` 选择此后端；`scope` 必须在项目允许写路径内。提交前验证 Git 顶层、HEAD、CLI 参数和自动接管绑定。缺失能力时拒绝创建任务。`doctor` 分开报告只读和原生写入能力。

## W2：worktree 与执行

为每个任务以提交时的 HEAD 建立 `codex1cc/<task_id>` 分支和工具管理的 worktree。保存共享文件内容及哈希，记录源工作区是否有未提交改动。复用现有进程事件、提问、时间和 USD 预算；写入模式开放 `Read/Glob/Grep/Edit/Write/Bash`，在配置允许的信任模式中非交互运行。日志、令牌和返回数据仍需脱敏。

## W3：结果、恢复与清理

结束时记录基线与最终提交、提交列表、未提交状态、改动路径和超出任务声明范围的路径。Codex 对照验收标准检查文件与测试。`complete_task` 只登记审查，不合并或删除 worktree。取消、失败和异常保留现场。执行器重启后不重交不确定轮次；进程归属、费用或会话状态不能确认时要求人工处理。后续增加经明确授权的任务工作树清理命令，并保证绝不删除不归本工具拥有的目录或未推送提交。

## W4：验收门槛

1. 模拟 CLI 测试覆盖提交去重、同项目互斥、只读回归、工作树隔离、本地提交、越界改动提示、问题/回答、取消、崩溃和自动接管回执。
2. 临时非敏感 Git 项目完成一次真实 CC 编码、测试、本地提交与 Codex 审查；记录 CLI/平台版本、提交 SHA、测试输出和事件状态。
3. Linux、WSL、macOS 分别验证并记录。未经真实验证的平台只标为未验证。真实费用与中断轮次的累计成本未知时停止续接。

当前实现覆盖 W1/W2 的主路径、W3 的交付和现场保留，以及 W4 的模拟自动接管和一次真实临时项目成功交付。真实写入任务的 Codex 自动审查、异常恢复与跨平台门槛以验证记录为准，不因代码已合并而自动视为通过。
